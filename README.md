# イベント受付システム v1.4.0

Google Form → QRメール自動送信 → 暗号化名簿 → iPhone 1台でオフライン受付、までをつなぐ一式です。事前準備・書き出しにはPCを使い、当日はiPhone 1台で完結します。こちらから公開・フォームへの回答・実メール送信は行っていません。

**最初にすることは2つです。**

1. このフォルダーをGitHubへアップロードし、Pagesの公開元を `main` の `/docs` にする。
2. 回答先スプレッドシートのApps Scriptへ、`apps-script` 内の2つの `.gs`、`Export.html`、設定をコピーする。

その後、実際のiPhoneと自分宛ての申込で、本番前の通し確認をしてください。

## メール本文の更新（2026年10月21日）

2027年2月27日(土) 9:30〜11:30の開催案内、活動内容、対象、場所と地図リンク、持ち物、備考をメール本文へ追加しました。QRは「他の方への共有はお控えください。」と「当日、携帯電話を…」の間に表示し、「受付用QRコード.gif」としても添付します。宛名は引き続き「名前（参加者本人）」の氏名＋様、受付番号はその申込の番号です。

保存後に送るメールへ反映されます。すでに届いたメールの本文は変わりません。新しい本文を案内したい申込だけ、元の回答シートで1行選び、**イベント受付 → 選択した1行のメールを手動で再送**を実行してください。同じQR・受付番号で再送します。自動で過去の申込へ一斉再送する変更は含みません。

文面の見本は `samples/メール見本.html`、プレーンテキストは `samples/メール見本.txt` です。架空の宛名・QRを使用しています。

## 今回の仕様

- 対象：第4回 笠戸島白浜海岸をキレイにしよう！
- Google Formの「テストにする」はオフで使用できます。採点・点数・正解データを使いません。
- 名簿はPCの書き出し画面でAES-256-GCMにより暗号化し、暗号化済みのJSONだけをiPhoneへ渡します。平文CSVの取り込みはありません。
- アプリの起動用パスフレーズ・自動ロックはありません。保存した名簿と受付記録を自動で開きます。名簿ファイルとバックアップファイルの暗号化には、引き続きパスフレーズを使います。
- 旧版のパスフレーズ付き記録が残っていても、サイト入口での入力は不要です。旧版の暗号文を別に保管し、受付画面を先に開きます。旧版の記録の復号・引き継ぎは「準備・保存」から任意で行えます。
- 1申込につきQRは1つ。子ども・保護者の中から、来場した方だけ個別に受付します。
- メールと受付画面で使う受付番号は **EV2701-0001** からの連番です。QRに入れるランダムな受付IDは別に保持し、発行済みのQRもそのまま使います。受付番号・氏名・以前の受付IDで手動検索できます。
- メール冒頭はフォームの「名前（参加者本人）」の氏名＋「様」です。「他の方への共有はお控えください。」の後、携帯電話の案内の前にQRを本文内表示し、同じ画像を **受付用QRコード.gif** として添付します。
- 追加人数は0以上の整数を自由入力できます。追加10名・100名という制限は設けません。追加氏名欄は本人を含めず、1人1行です。受付名簿全体の処理上限は、本人・保護者・仮枠を合わせて1万名です。
- 保護者は代表者名、2人目以降は「同伴保護者2」などと表示します。
- **人数と氏名が一致しなくてもQRを送ります。理由を「KSD当日確認」列へ記録し、受付画面にも表示します。訂正依頼メールは送りません。**
- 二重受付を検出します。名前検索、受付取消、当日確認メモ、CSV出力、暗号化バックアップに対応します。
- イベント名・送信者名・署名・問い合わせ先・ホームページは、スクリプト先頭の `CONFIG` で変更できます。日時・活動場所・持ち物などの開催案内は、`qrMessage_` 内の `eventGuide` で変更できます。

## 1. GitHub Pagesで公開する

1. GitHubで、この受付アプリ用のリポジトリを作ります。無料プランでPagesを使う場合は、利用できる公開範囲をGitHubの画面で確認してください。
2. ZIPを解凍し、その中の `docs`、`apps-script`、`samples` などを、リポジトリ直下へアップロードします。`docs/index.html` が存在する階層にします。ZIPそのものを置くだけでは動きません。
3. リポジトリの **Settings → Pages → Build and deployment** を開きます。
4. **Source: Deploy from a branch / Branch: main / Folder: /docs** を選び、保存します。
5. GitHubが表示した `https://…github.io/リポジトリ名/` のURLを開きます。`/docs/` をURLの末尾に加える必要はありません。
6. HTTPSで表示されることを確認します。

**実際の参加者一覧・フォーム回答・受付結果・バックアップ・パスフレーズは、GitHubへアップロードしないでください。** 参加者データは、公開後のアプリへファイル選択で取り込みます。ソースコードに埋め込む必要はありません。

公開方法の公式説明：[GitHub Pagesの公開元設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

HTMLファイルを「ファイル」アプリから直接開く運用には対応しません。カメラ・暗号化・オフライン起動のため、最初はHTTPSのURLから開いてください。

## 2. Google FormからQRを自動送信する

### スクリプトを入れる

1. Google Formの編集画面で **回答 → スプレッドシートにリンク** を選び、回答先スプレッドシートを開きます。
2. 元の回答が並ぶシート（例：「フォームの回答 1」）を選択します。
3. **拡張機能 → Apps Script** を開きます。今回は**フォーム側ではなく、回答先スプレッドシート側**に紐付けます。
4. 既存のコードがある場合は控えを取り、付属の `apps-script/Code.gs` を貼り付けます。
5. Apps Scriptでスクリプトファイルを追加し、名前を `QRCode` にして、`apps-script/QRCode.gs` の全文を貼り付けます。画面上では `.gs` が自動で付きます。
6. **HTMLファイル**を追加し、名前を `Export` にして、`apps-script/Export.html` の全文を貼り付けます。スクリプトファイルではなくHTMLファイルです。
7. Apps Scriptの **プロジェクトの設定 →「appsscript.json」マニフェスト ファイルをエディタで表示する** を有効にします。表示された `appsscript.json` を付属ファイルの内容にします。
8. `Code.gs` 先頭の `CONFIG` を確認し、保存します。`EVENT_NAME` はイベント名、`ORGANIZER` は送信者名、`SIGNATURE_NAME` はメール末尾の署名、`CONTACT_EMAIL` は問い合わせ先と返信先、`WEBSITE_URL` はホームページです。初期値はご指定の文面・署名・連絡先です。`RECEIPT_PREFIX` は `EV2701` のまま使用し、採番開始後は変更しないでください。

`CONTACT_EMAIL` が空欄なら、メールへの返信先は送信元Googleアカウントです。別の問い合わせ先が決まったら、ここへ設定できます。

フォームの自動収集メール欄と手入力の「メールアドレス」欄の両方がある場合、QRの送信先には手入力欄を使います。複数の手入力メール欄があって判別できない場合は、誤送信しないよう列設定の確認を求めます。

### 自動送信を開始する

1. 元の回答シートを選んだ状態で、Apps Scriptの関数一覧から **setupReception** を選び、1回実行します。
2. Googleの権限画面で内容を確認し、使用する主催者のアカウントで許可します。必要な権限はスプレッドシートの読書き、メール送信、トリガーの管理、シート内メニューの表示です。受信メールを読む権限や外部HTTP通信の権限は使いません。
3. **回答スプレッドシートのタブへ戻り**、「自動送信の開始」で「はい」を押します。続いて「設定しました」の「OK」も押します。確認画面が開いている間は、Apps Script側の実行も待機状態です。
4. 回答スプレッドシートを再読み込みすると、**イベント受付** メニューが表示されます。
5. 新規フォーム回答からQRが自動送信されます。**handleReceptionSubmit は手動実行しません。** 実際にフォームへ回答して試します。

Webアプリとしての「デプロイ」は不要です。スクリプトのソースやGoogleの認証情報をPWAへ渡す設定も不要です。

以前のQR送信処理がある場合は、その古い送信トリガーを停止してから切り替えてください。このコードで発行する `KSD4-…` のIDと、既存の別形式のQRには互換性がありません。

### すでにある申込へ送る場合

初期設定だけでは、設定前の回答へ一斉送信しません。

送信対象にする場合は、**イベント受付 → 既存の未処理申込を送信対象にする** を使います。送信済みの申込を再び送る場合は、元の回答シートで対象の1行を選び、**選択した1行のメールを手動で再送** を使います。再送しても受付ID・受付番号は同じです。

受付番号は、受付IDがある申込へ未採番のものから割り当てます。初回は `EV2701-0001` から始めます。並べ替えや再送で番号は変わらず、削除した申込の番号や予約済みの番号は再利用しません。保存中のエラーなどで欠番になる場合があります。「KSD受付番号」とScript Propertiesのカウンターを手動で変更・削除しないでください。旧版の送信済み申込へ番号を付けても、メールを自動で再送することはありません。

送信待ちは10分ごとに再処理します。Googleの送信枠が足りない場合も、人数不一致と混同せず「送信待ち」として残します。Googleの公開上限は、個人用アカウントで通常100宛先/日、Google Workspaceで通常1,500宛先/日です。他の自動送信と枠を共有し、契約やGoogle側の変更で異なります。[Google公式の割り当て](https://developers.google.com/apps-script/guides/services/quotas)を確認してください。

### 送信・確認状態を見る

回答シートの右側に管理列を追加します。元のフォーム回答は上書きしません。

| 列 | 内容 |
| --- | --- |
| KSD受付ID | QRに入れるランダムなID。編集しないでください |
| KSD受付番号 | メール・手動受付で使うEV2701-0001からの連番。編集しないでください |
| KSD状態 | 送信済み、送信済み（当日確認あり）、送信待ちなど |
| KSD確認ハッシュ | 申込内容の変更を検出するための値 |
| KSD送信日時 | QRメールを送信した日時 |
| KSDエラー | 実際のメール送信・設定などの問題 |
| **KSD当日確認** | **人数と氏名の不一致など、当日に確認する理由** |
| KSD名簿人数 | 仮枠を含む名簿上の人数。実際の来場人数ではありません |

「送信済み」はGoogleのメール送信APIが処理を受け付けた状態で、相手の受信箱への到達保証ではありません。迷惑メールも含めて確認してください。

送信の途中で結果が分からなくなった場合は「要確認」とし、自動では再送しません。送信済みの可能性があるためです。これは入力人数の不一致による送信停止とは別です。送信状態を確認して、必要なら手動再送してください。メールアドレスの形式が不正な場合やGoogleの制限時には、メールを送れません。

## 3. iPhoneを準備する

1. オンラインのiPhoneの**Safari**で、GitHub PagesのURLを開きます。
2. Safariの共有メニューから **ホーム画面に追加** を選びます。「Webアプリとして開く」の項目がある場合は有効にします。
3. 追加した**ホーム画面のアイコンから**開きます。パスワードの設定や入力は不要で、受付画面が表示されます。
4. 以降は、このアイコンから起動して運用します。Safariの通常タブとは保存領域が分かれる場合があるため、名簿の取り込みもアイコンで開いた画面で行います。

Apple公式の説明：[iPhoneのSafariでウェブサイトをアプリにする](https://support.apple.com/ja-jp/guide/iphone/iphea86e5236/ios)。

端末内の記録は、自動生成して端末に保存した暗号鍵で暗号化します。起動時にはその鍵で自動的に開くため、アプリを操作できる人は名簿も見られます。iPhoneのFace ID・パスコードで端末を保護してください。端末内の鍵やデータが失われた場合に備え、暗号化バックアップを保存してください。

## 4. 受付名簿を取り込む

1. PCの回答先スプレッドシートで **イベント受付 → 受付名簿を暗号化して書き出す** を選びます。最新の名簿を自動で生成します。
2. 書き出し画面で、10文字以上の**受け渡し用パスフレーズ**を2回入力し、「名簿を読み込み、暗号化する」を押します。
3. 暗号化が完了したら、**暗号化名簿を保存** を押し、JSONファイルを保存します。平文CSVをダウンロードする操作は不要です。
4. この暗号化済みJSONだけを、AirDropなどでiPhoneの「ファイル」に渡します。パスフレーズはファイルと別の安全な方法で控えてください。
5. ホーム画面の受付アプリを開き、**準備・保存 → 暗号化名簿を選ぶ** を押します。
6. JSONを選び、書き出し時の**受け渡し用パスフレーズ**を入力します。内容を確認して取り込みます。復号や検証に失敗した場合、現在の記録は変更しません。
7. 件数・人数と、**オフライン準備完了** の表示を確認します。
8. **暗号化バックアップを保存** を押し、バックアップ用パスフレーズを2回入力します。共有メニューの「ファイルに保存」などで、保存先にファイルができたことを確認します。このパスフレーズは復元時に必要なので、別の安全な場所へ控えてください。

受付名簿に含めるのは、受付ID、人物ID、氏名、区分、申込代表者、受付メモ、受付番号だけです。電話番号、住所、メール、所属、学年はPWAへ取り込みません。撮影・掲載の同意と当日確認の理由は受付メモに含めます。

名簿のCSVデータは書き出し画面のメモリ内で暗号化し、ファイルには暗号文だけを保存します。受け渡し用パスフレーズをApps Scriptのサーバーへ送ったり、スプレッドシートへ記録したりしません。Google側の原本や、HTTPSで書き出し画面へ読み込むデータまでなくなるわけではありません。

**ファイル用パスフレーズは2つの用途があります。**「受け渡し用」は名簿ファイルを開くため、「バックアップ用」は保存した受付記録を復元するためです。いずれも10〜200文字で、同じ長い言葉を設定することも、別々にすることもできます。アプリ起動時の入力は不要です。iPhoneでは受け渡し用で復号した後、端末に保存した鍵で暗号化し直します。ファイル用パスフレーズは保存しません。以前に作った暗号化ファイルも、それを保存したときのパスフレーズで引き続き開けます。

「暗号化名簿」と「暗号化バックアップ」は別の形式です。名簿は**準備・保存 → 暗号化名簿を選ぶ**、バックアップは**準備・保存 → 暗号化バックアップから復元**で選んでください。起動できない場合の画面からもバックアップを選べます。名簿を取り込む操作では、既存の受付済み記録を消して上書きしません。

## 5. 人数と氏名が違う場合

QRは通常どおり送ります。コードは、名前を勝手に削除して人数に合わせません。

追加氏名が100名を超える場合も氏名を残します。名簿全体が1万名を超えるときは、前回の受付名簿を保持して書き出しを停止し、エラーを表示します。1件の申告だけで上限を超える場合は「KSD当日確認」にも理由を残します。極端に大きい申告人数から無制限に仮枠を作ることはありません。QR送信は引き続き行いますが、その状態の名簿は書き出せないため運営側で原本の確認が必要です。

| 申込内容 | 名簿・受付画面 |
| --- | --- |
| 追加3名、名前2名分 | 記入された2名＋「氏名要確認」の仮枠1つ。不一致理由を表示 |
| 追加1名、名前2名分 | 記入された2名を残し、不一致理由を表示 |
| 同じ名前を重複記入 | 名前を残し、重複の理由を表示 |
| 保護者人数を判別できない | 仮の保護者枠と確認理由を表示 |

当日はQRを読んだ画面の **当日確認** を見て、実際の人数・氏名を確認します。必要なら **当日確認の記録** にメモを残し、確認済みにできます。メモを保存する操作と受付の確定は別です。

実際に来場した方だけを選んで受付し、来ていない仮枠は選びません。「未受付の枠」には仮枠も含まれるので、参加予定の実人数と同じとは限りません。確認メモや受付結果はGoogleへ自動同期せず、端末の暗号化バックアップと受付結果CSVへ含めます。

## テスト申込を1件ずつ削除する

1. 元のフォーム回答シートで、削除したいテスト申込の**1行だけ**を選択します。受付名簿の行や見出し行は対象にできません。
2. **イベント受付 → 選択したテスト申込を削除** を選びます。
3. 表示された行番号・氏名・受付番号を確認し、消してよいテスト申込であれば「削除」と入力します。取り消す場合はキャンセルします。
4. 選択した回答行の内容と、同じ受付IDの受付名簿を消します。行そのもの・フォーム本体・見出し・ほかの申込・採番カウンターは残します。削除した受付番号は再利用しません。

確認中に対象行が編集・並べ替えされた場合は削除を止めます。途中の書込に失敗した場合は対象データの復元を試み、復元にも失敗した場合は確認すべき箇所を表示します。

**Google Form側の「回答」に保存された原本、送信済みメール、iPhoneへ取り込み済みのデータは消しません。** 受付用のスプレッドシート2枚が削除対象です。iPhoneへは、最新の暗号化名簿を改めて取り込んでください。受付済みのテスト人物が新名簿から消えると、受付記録を保護するため取り込みを止めます。端末内がすべてテストデータであれば、「準備・保存 → この端末の名簿と記録を削除」でテスト分を消してから、新しい名簿を取り込みます。実際の受付記録が混ざっている場合は、消さずに別途確認してください。

## 6. 当日の操作

1. ホーム画面のアイコンで開きます。パスフレーズの入力は不要です。
2. **カメラを起動** を押し、カメラを許可します。iPhone標準のカメラアプリではなく、受付アプリ内のカメラを使います。
3. 参加者が提示したQRを読みます。インターネットのURLは開かず、端末内の名簿と照合します。
4. 氏名や当日確認の表示を見て、来場した子ども・保護者を選び、**○名の受付を確定** を押します。
5. **受付を保存しました** の表示を確認します。保存に失敗した場合、受付済みにはしません。
6. 次の方は、再度カメラを起動します。読取り後はカメラを止めて、電池の消費を抑えます。

同じQRを再提示しても、受付済みの方は選べません。後から到着したメンバーだけ受付できます。QRがない場合は **名簿** で氏名・代表者名・受付番号を検索するか、**QRが読み取れないとき → 受付番号・受付ID** に `EV2701-0001` などを入力します。以前のメールに記載された `KSD4-…` も引き続き使えます。連番の受付番号を入れた自作QRは読み取らず、QR読取では付属スクリプトのランダムIDだけを受け付けます。

自動ロックはありません。アプリを閉じても、次回はパスフレーズなしで保存済みの記録を開きます。バックグラウンドへ移動するとカメラは停止します。受付記録は操作のたびに暗号化して保存するため、手動保存ボタンを押す必要はありません。

名簿を再取り込みしても、同じ人物IDの受付記録を引き継ぎます。ただし、受付済みの方を削除したり別人に変えたりする名簿は拒否します。申込内容が変わったグループは、以前の確認メモを残して確認済み状態を解除します。

## 7. 終了後の保存・復元

- **暗号化バックアップを保存**：名簿、受付日時、当日確認メモを暗号化したJSONです。保存時に10文字以上のバックアップ用パスフレーズを設定し、その言葉で復元します。端末用の暗号鍵はファイルに含めません。別の安全な保存先へ控えを置いてください。
- **受付結果をCSVで保存（暗号化なし）**：氏名、受付状態、日本時間の日時、当日確認のメモを出力します。個人情報を含むため、公開場所に保存しないでください。
- **復元**：「準備・保存」の「暗号化バックアップから復元」でJSONを選び、バックアップ保存時のパスフレーズを入力します。現在の記録を置き換える前に確認します。旧版のバックアップも、旧版のアプリ用パスフレーズで復元できます。
- **削除**：必要なファイルの保存を確認した後、「この端末の名簿と記録を削除」で削除できます。

## 本番前の通し確認

実際の受付に使うiPhoneで、以下を確認してください。

1. 自分のメールアドレスで、実際のフォームからテスト申込する。
2. 「名前（参加者本人）」の氏名＋「様」で始まるメールを受信し、受付番号、指定位置のQR本文内表示、添付名「受付用QRコード.gif」、問い合わせ先を確認する。人数が違う申込でもQRが届き、KSD当日確認に理由が残ることを確認する。
3. PCの書き出し画面で名簿を暗号化し、JSONだけをiPhoneへ渡して、ホーム画面から起動したアプリへ取り込む。
4. iPhoneを機内モードにし、Wi-Fiも切る。アプリを終了して、ホーム画面のアイコンから開き直す。
5. QR読取、個別受付、同じQRの再読取、名前・受付番号での検索、受付番号の手入力、当日確認メモを試す。
6. アプリをもう一度開き直し、受付が残っていることを確かめる。
7. バックアップと受付結果CSVを「ファイル」に保存し、バックアップを復元する。
8. 本番前にテスト用の記録を削除し、本番の名簿を取り込む。テスト名簿と本番名簿を混ぜない。

`samples/暗号化テスト名簿.json` と同じフォルダーのQR画像でも、アプリだけの練習ができます。練習用の受け渡し用パスフレーズは `samples/README.md` に記載しています。本番には使わないでください。QRを印刷しておけば、当日に必要な端末はiPhone 1台だけです。

## v1.2.0以前から更新する場合

1. 更新前に、現在のアプリから暗号化バックアップを保存します。
2. 回答先スプレッドシートに紐付いたApps Scriptの **`Code.gs` とHTMLファイル `Export` を更新版の全文に置き換えます**。`RECEIPT_PREFIX`、`SIGNATURE_NAME`、`WEBSITE_URL` などが追加されているため、旧版のCONFIG全体を貼り戻さず、必要な設定値だけ確認してください。`QRCode.gs` と権限は前版と同じです。v1.0.0からの場合は、HTMLファイル `Export` を追加してください。既存のApps ScriptプロジェクトとScript Propertiesを維持し、初期設定の再実行は不要です。
3. スプレッドシートを再読み込みし、**イベント受付 → 受付名簿を最新にする** を選びます。「KSD受付番号」列が追加され、既存の受付IDに番号が付きます。この操作でメールは送信しません。発行済みのQR・受付IDは変更しません。
4. GitHub Pagesの **`docs` フォルダーを一式更新**します。公開先URLは変更しないでください。iPhoneをオンラインにして開き、同じURLのSafariタブを閉じて、Appスイッチャーで受付アプリのプレビューを上へスワイプして終了してから、ホーム画面のアイコンで開き直します。最下部の **v1.4.0** を確認します。ホーム画面へ戻るだけでは終了しない場合があります。旧版の記録が残っていても、入口のパスワード入力はありません。
5. PCで名簿を暗号化して書き出し直し、iPhoneへ取り込みます。同じ人物IDの受付済み記録・確認メモを保持しながら、受付番号を追加します。サイトデータやアプリを削除する必要はありません。
6. 既に送信したメールの本文は変わりません。新しい文面を送る必要がある申込だけ、元の回答シートで1行選び、**選択した1行のメールを手動で再送**してください。自分宛てのテストメールで本文内の画像位置と添付名を確認してから本番運用してください。

旧版の受付番号なし名簿・暗号化バックアップも読み込めます。番号を反映するには最新名簿を再取り込みしてください。新しい名簿を取り込んだ後に受付番号なしの旧名簿を再取り込みしても、既存の番号は消しません。

ホーム画面へ追加するときの名称は「イベント受付システム」です。既に追加済みのアイコン名は、自動で変わらない場合があります。名称変更のためにアプリやサイトデータを削除しないでください。

## v1.3.0〜v1.3.2からv1.4.0へ更新する場合

1. 受付記録がある場合は、更新前に暗号化バックアップを保存します。
2. Apps Scriptの **`Code.gs` を更新版の全文に置き換えて保存**します。v1.3.2のメール本文更新版を含み、学年の取り込みと選択したテスト申込の削除を追加しています。v1.3.2より前の場合はHTMLファイル `Export` も更新してください。`QRCode.gs`、権限、トリガー、Script Propertiesはそのままで、`setupReception` の再実行は不要です。
3. スプレッドシートを再読み込みし、**イベント受付 → 受付名簿を最新にする** を1回実行します。学年・年齢の列を追加し、古い人数警告も再判定します。メール再送や受付番号・QRのIDの変更は行いません。
4. GitHubの **`docs` フォルダーをv1.4.0へ一式更新**します。iPhoneをオンラインにしてアプリを開き、同じURLを開いているSafariタブを閉じます。Appスイッチャーで受付アプリのプレビューを上へスワイプして終了し、もう一度アイコンから開いて **v1.4.0** を確認してください。アプリやサイトデータは削除しません。[Appleのアプリ終了手順](https://support.apple.com/ja-jp/109359)。
5. 最新の名簿を暗号化して書き出し、iPhoneへ取り込みます。名簿とバックアップの保存には10文字以上のパスフレーズを使えます。以前の暗号化ファイルも保存時の言葉で開けます。通常の保存済み記録はそのまま自動で開きます。

旧版のパスフレーズ付き記録が残っている場合も、暗号文を別に保管して受付画面を先に開きます。まだ旧版の記録を引き継いでいない場合、現在の画面は空の名簿から始まります。最新の暗号化名簿を取り込んで受付を始めることもできます。

### 旧版の記録が必要な場合だけ行う操作

「準備・保存 → 旧版の記録を引き継ぐ（任意）」で保管分を選び、「旧版の記録を引き継ぐ」を押すと、以前のパスフレーズで復号できます。これは保管したデータを読む操作で、サイトを開く条件ではありません。旧版と現在の記録を合わせ、どちらかで受付済みの人物は受付済みとして引き継ぎます。重なる確認メモは現在のものを優先し、人物情報や受付番号が食い違う場合は変更せず停止します。保管した原本は引き継ぎ後も残ります。

「旧版の暗号化ファイルを保存」はパスフレーズを入力せずに原本を保存できます。復号には以前のパスフレーズが必要です。通常の「暗号化バックアップを保存」には現在の受付データだけが入るため、必要な保管分は別に保存してください。「この端末の名簿と記録を削除」は保管分も含めて削除します。

## よくある問題

| 状態 | 対処 |
| --- | --- |
| QRが届かない | 迷惑メール、KSD状態、KSDエラー、送信枠、Apps Scriptの実行履歴を確認 |
| 要確認（QR送信中） | 送信済みの可能性あり。状態を確認し、必要なら手動再送 |
| アプリが「名簿にありません」 | 最新の暗号化名簿と、その名簿に対応するQRか確認 |
| 入口で「ロックを解除」が出る | v1.4.0のdocsを一式公開したか確認し、オンラインで開いた後に同じURLのタブと受付アプリを終了して開き直す。サイトデータは削除しない |
| 暗号化名簿ではないと表示 | 「受付名簿を暗号化して書き出す」で保存したJSONか確認。バックアップは「暗号化バックアップから復元」で選ぶ |
| 名簿を復号できない | PCで書き出したときの受け渡し用パスフレーズを入力 |
| 書き出し画面が開かない | PC版スプレッドシートを使用し、Apps ScriptへHTMLファイル Export を追加したか確認 |
| オフライン準備未完了 | オンラインに戻し、ホーム画面のアイコンから再起動 |
| カメラを許可できない | SafariのWebサイト設定を確認。名前検索でも受付可能 |
| 別の画面で更新された | この画面を再読み込みし、最新の保存状態を読み込む |
| 保存した暗号鍵が見つからない | 記録を自動で初期化せず停止します。暗号化バックアップから復元してください |
| ファイル用パスフレーズを忘れた | 名簿はPCで新しいパスフレーズで書き出し直せます。バックアップは、アプリ内の記録が残っていれば新しいパスフレーズで保存し直せます。失われた記録とバックアップしかない場合は、そのパスフレーズが必要です |

アプリは1台運用です。複数のiPhone・別ブラウザー間の受付同期はありません。運用中は同じURL・同じホーム画面のアイコンを使い、サイトデータの削除やアプリの再インストールを避けてください。残量と充電手段も準備してください。
